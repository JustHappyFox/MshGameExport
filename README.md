# autoedit.ink

Telegram Mini App и бот: вставляют рекламную интеграцию ровно в центр видео и
отдают ссылку на готовый файл.

Кадр основного видео замирает, поверх него играет вставка с вырезанным
хромакеем, после её окончания видео продолжается с того же кадра. Звук
основного видео на это время тоже встаёт на паузу.

## Требование рекламодателя

Раскрытая панель должна занимать **не менее 25% кадра** — это проверяет бот на
их стороне. Порядок работы такой:

1. **Чёрные поля.** Если во входном видео есть letterbox, он срезается. Иначе
   его площадь попадёт в знаменатель и процент окажется занижен искусственно.
   После срезания «кадр видео» и «весь кадр файла» — это одно и то же, поэтому
   наш замер сходится с их замером.
2. **Замер до сжатия.** Считается след баннера по альфа-маске после хромакея:
   зелёный фон и скругления углов в площадь не входят. Берётся худший кадр
   раскрытой фазы.
3. **Решение.** Проходит порог — кадр не трогаем вообще. Не проходит — высота
   кадра уменьшается ровно настолько, чтобы порог взялся (цель
   `TARGET_COVERAGE`, по умолчанию 25.35% — с запасом на округления).
4. **Проверка.** Готовая геометрия перепроверяется: вставка кладётся на чистую
   магенту тем же конвейером, считается всё, что не магента. Если порог не
   выдержан, файл не отдаётся, задача падает с ошибкой.

Порог зависит только от пропорций: панель занимает ≥25% при `H ≤ 1.748 × W`.
Поэтому 9:16 (720×1280 → 24.58%) не проходит и сжимается на 40 px до 720×1240,
а 16:9 проходит с большим запасом (77.85%) и не сжимается.

Замерить что угодно вручную:

```bash
python3 tools/measure.py видео.mp4          # что увидит их бот
python3 tools/measure.py --plan видео.mp4   # + план обработки и перепроверка
python3 tools/measure.py --geometry 720x1280
```

## Как работает

| Компонент | Что делает |
|---|---|
| `app/api.py` | FastAPI: приём видео из Mini App, статус задачи, подписанные ссылки |
| `app/worker.py` | отдельный процесс, разбирает очередь, гоняет ffmpeg |
| `app/bot.py` | aiogram: кнопка Mini App, приём видео прямо в чат |
| `app/video/probe.py` | геометрия, поворот, звук, поиск чёрных полей |
| `app/video/banner.py` | покадровый замер вставки по альфа-маске, кеш |
| `app/video/render.py` | план, сборка, проверка результата |
| `web/` | Mini App |
| `assets/banner.mp4` | сама интеграция (зелёный фон) |

Загрузка идёт из браузера напрямую на сервер, поэтому **лимита Telegram на
20 МБ нет** — упор только в `MAX_UPLOAD_BYTES` и `client_max_body_size`. Если
прислать видео в чат боту, Telegram отдаст файл не больше 20 МБ; бот об этом
честно скажет и предложит приложение.

Готовый файл выдаётся по ссылке `/d/<токен>`: приложение проверяет HMAC-подпись
и срок, а байты отдаёт nginx через `X-Accel-Redirect`. Файлы и записи чистятся
по `RETENTION_HOURS`.

## Установка

```bash
git clone <репозиторий> autoedit && cd autoedit
sudo bash deploy/install.sh
```

Скрипт идемпотентный — им же и обновляться. Что он делает: ставит ffmpeg,
nginx и python, создаёт пользователя `autoedit`, раскладывает код в
`/opt/autoedit`, данные в `/var/lib/autoedit`, ставит три systemd-юнита, кладёт
конфиг nginx и прогревает кеш замеров.

Дальше руками:

1. Токен от [@BotFather](https://t.me/botfather) в `/etc/autoedit/autoedit.env`:
   ```
   BOT_TOKEN=...
   PUBLIC_BASE_URL=https://autoedit.ink
   ```
2. Сертификат, если его ещё нет:
   ```bash
   certbot certonly --nginx -d autoedit.ink -d www.autoedit.ink
   nginx -t && systemctl reload nginx
   ```
3. В @BotFather: `/setmenubutton` → бот → URL `https://autoedit.ink/`
4. `systemctl restart autoedit-api autoedit-worker autoedit-bot`

DNS: `autoedit.ink` и `www.autoedit.ink` должны смотреть A-записью на сервер.

## Настройки

Всё в `/etc/autoedit/autoedit.env`, полный список — в `.env.example`.
Самое нужное:

| Переменная | По умолчанию | Смысл |
|---|---|---|
| `MIN_COVERAGE` | `0.25` | порог, который проверяет бот рекламодателя |
| `TARGET_COVERAGE` | `0.2535` | цель при сжатии — чуть выше порога |
| `CROP_BLACK_BARS` | `1` | срезать чёрные поля до замера |
| `ALLOWED_USER_IDS` | пусто | пусто = пускать всех, иначе список telegram id |
| `MAX_UPLOAD_BYTES` | 2 ГБ | держать в согласии с `client_max_body_size` |
| `LINK_TTL_HOURS` | `48` | сколько живёт ссылка |
| `RETENTION_HOURS` | `72` | когда удалять файлы |
| `X264_CRF` | `20` | качество: меньше — лучше и тяжелее |

## Эксплуатация

```bash
systemctl status autoedit-api autoedit-worker autoedit-bot
journalctl -u autoedit-worker -f
curl -s localhost:8081/api/health
```

Рендер идёт примерно в реальном времени: ролик 34 с собирается за ~35 с на
одном ядре. Воркер один и берёт задачи по очереди — если нужно параллельно,
поднимается второй экземпляр юнита (`claim_next` забирает задачу атомарно, так
что гонки не будет).

Замена интеграции: положить новый файл в `assets/banner.mp4` (зелёный фон,
`0,254,0`) и перезапустить воркер. Кеш замеров инвалидируется сам — ключ
включает размер и mtime файла.

## Тесты

```bash
python3 tests/test_e2e.py          # подпись, загрузка, очередь, рендер, ссылки
python3 tests/test_e2e.py своё.mp4
```

Тест поднимает приложение через `TestClient`, гоняет настоящий ffmpeg и
проверяет 17 пунктов: отказ без подписи и с чужой подписью, отказ по формату и
пустому файлу, изоляцию задач между пользователями, взятие задачи воркером,
выдержку порога, отдачу файла, битый и просроченный токены, историю и уборку по
сроку хранения.
